feat(domain): implement Rule value type

Implements Rule, the fundamental building block of the detection engine:
a named regex-based attack signature with a category (SQL injection,
XSS, path traversal, command injection), a set of request targets to
inspect (query/body/headers), and a severity. Closes #1.

- NewRule is the only way to construct a Rule — fields are unexported,
  only accessed via getters (ID(), Category(), etc.). This guarantees
  every Rule in memory has passed fail-fast validation; there's no
  struct-literal escape hatch that skips it.
- The targets slice is copied on construction, not aliased to the
  caller's slice — mutating the original slice after creating a Rule
  must never leak into the (conceptually immutable) Rule.
- The regex pattern is compiled once at construction time, not on every
  Matches() call — Rule will be evaluated against every request that
  hits the proxy, so paying the regex-compilation cost once matters for
  RNF01 (minimal latency overhead).
- NewRule returns an error rather than panicking: rules are expected to
  come from an external config file (rules.yaml, upcoming), so a
  malformed rule is an ordinary expected configuration error, not an
  exceptional program condition.

Tests: 11 tests, 100% coverage, covering the happy path and every
validation failure mode (empty id, invalid category/target/severity,
invalid regex pattern) plus the slice-aliasing regression case.
